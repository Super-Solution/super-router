# Conformance data

Language-neutral test data for the Super Router core. The TypeScript implementation in
`packages/core` is the reference; every other backend must reproduce these cases exactly.

| File | What it pins |
| --- | --- |
| `routing.v1.json` | `route`: the hard limits (task kind, enabled, model, region, labels, output tokens, media meters, budget) in order with their exclusion reasons, then weighted scores and ordering. Scores are IEEE doubles and must match exactly; offering ids use `[a-z0-9]` so the id tie-break agrees across languages |
| `contracts.v1.json` | Parsing untrusted JSON into a `service` or an `invocation`: 60 + 84 cases (sampling, reasoning effort, tags, cache, structured output and the output and timeout limits included). Valid ones carry the parsed value with defaults filled (and, for invocations, the canonical JSON that feeds the idempotency digest); invalid ones carry `invalid_request`. String limits count code points. Generated by `scripts/export-contracts-conformance.ts` |
| `dataplane.v1.json` | Hand-authored and normative: 29 scenarios that run the whole data plane (publish, grant, infer, replay, fallback, unknown outcomes, cancel, expiry, bucket order, recovery) against any store. Passes on the in-memory and PostgreSQL stores of every backend. Steps compare by partial match; `"$name"` refers to an earlier id and `">0"` to a positive amount |
| `tools.v1.json` | Tool calling: 91 invocation cases (tools, tool choice, tool calls and results, image parts, several system messages; valid ones carry the parsed value and canonical JSON), the shared `offering`, and for `openai` and `anthropic` the exact upstream request body of 15 invocations (sampling and reasoning effort included for the providers that carry them; automatic caching is a top-level `cache_control` for Anthropic only) and the provider events of 10 recorded streams. Generated by `scripts/export-tools-conformance.ts` |
| `pricing.v1.json` | `charge` (customer charge for a usage record), `bound` (amount reserved before a call), `compile_credit_price` (exact units-per-credit rates into the wire price), including validation and error codes. The Rust copy adds `rate_card_charge` and `rate_card_bound` (see below) |

Atoms and totals are decimal strings, so no language needs a float or a fixed-width integer.

```bash
npx tsx scripts/export-conformance.ts          # regenerate pricing from the TypeScript reference
npx tsx scripts/export-routing-conformance.ts  # regenerate routing
npx tsx scripts/export-contracts-conformance.ts # regenerate parsing
npx tsx scripts/export-tools-conformance.ts    # regenerate tool calling
npx tsx --test tests/conformance.test.ts       # TypeScript still matches the generated files
npx tsx --test tests/dataplane.test.ts         # data plane scenarios on memory and PostgreSQL
(cd backends/go && go test ./...)              # Go port (PostgreSQL tests need a database, see its README)
(cd backends/python && pytest)                 # Python port (ruff check . && mypy for lint and types)
```

`dataplane.v1.json` is edited by hand: change a scenario only when behaviour changes on purpose, and run it on every store.
If pricing behaviour changes on purpose, regenerate, review the diff, and update every port.
`backends/rust/conformance` holds a copy of these files with the same cases first, followed by cases for features the
TypeScript reference does not have yet (custom billing units, structured output, downgrade policy, label evidence, the rate card).
`rate_card_charge` and `rate_card_bound` are written by `node scripts/export-rate-card-conformance.mjs`, which states the rate card rule once in
plain BigInt arithmetic as an oracle independent of both backends.
Rust and Go test against that copy; `tools.v1.json` is the same in both places.
A scenario in the Rust copy may carry a `health` object (optional `rate_limited_ms`): the runners then give the router a `HealthBook` with that cooldown (Rust and Go only; the reference and Python have none).

## Known lag (read this before trusting a green run)

`failure.v1.json` (`classify_failure`, plus `provider_responses`: real HTTP refusals the OpenAI and Anthropic providers
must turn into the same error) and `retry_after.v1.json` (`Retry-After` parsing) are shared by all four languages:
the TypeScript reference, Python, Go and Rust each run them, so a provider reads an upstream refusal the same way
everywhere. Two more files live only in `backends/rust/conformance` and are run by Rust and Go alone, so TypeScript and
Python do not implement what they pin: `health.v1.json` (the `HealthBook` state machine, which has no TypeScript or
Python port) and `provider-gemini.v1.json` (the Gemini request and stream mapping, plus the usage normalisation). The
`contracts`, `dataplane`, `pricing` and `routing` files there also carry extra cases for features the reference does not
have yet. Python additionally has no tool calling, images, structured output or rate cards (it refuses them before
reserving). `backends/README.md` has the per-language table. Closing this lag is tracked in
`docs/engineering/improvement-log.md`.
